    05 / Runtime paths

    Fast predictions stay isolated from heavyweight retraining

    P
    Synchronous path

    Online prediction

    A request reads one already-loaded snapshot and returns without touching MongoDB.

    • Token → Pydantic → clean text → TF-IDF → Random Forest
    • The vectorizer, model, and encoder come from one bundle
    • The abstention policy file is re-read per request
    • A throttled manifest check may safely reload a newer version
    T
    Background path

    Retraining lifecycle

    An accepted request starts one lock-owning background thread and two subprocesses.

    • Reserve feedback → snapshot → trainer → validator
    • Validation finishes before active.json can change
    • Activation or a human approval, then finalization, cleanup, and lock release
    E
    Caller path

    Express bridge

    The browser calls Express, never this service. Express adds the token and a request ID.

    • Saved merchant rules win before any ML call
    • Add-expense writes feedback; a 20:30 job triggers retraining at 100 pending
    • Predict and describe time out at 5 seconds and fail soft
    06 / Honest boundaries

    What this ML service guarantees—and where its limits are

    These distinctions keep the service explanation accurate and make its next engineering priorities visible.

    Guaranteed Capabilities

    Architectural guarantees and core operational safeguards enforced in code

    It does

    Keep live artifacts immutable

    Retraining writes a new run-specific dataset and model bundle; it never overwrites the files currently serving predictions.

    It does

    Fail closed on the operations token

    Eight of the twelve operations, including prediction and retraining, return 503 with no configured token and 401 with a wrong one. Only HEAD /, GET /, and the two health probes are open.

    It does

    Recover known crash windows

    Startup reconciles orphaned runs, reserved feedback, and mid-activation state using MongoDB plus manifest and bundle evidence.

    It does

    Abstain instead of forcing a guess

    Below 0.90 confidence the response is flagged abstained with reason low_confidence, still carries the best category, and the app shows it as a suggestion.

    Architectural Non-Goals

    Explicit out-of-scope responsibilities handled elsewhere in the architecture

    It does not

    Use an LLM for descriptions

    Description generation uses keyword rules, category templates, random selection, and one amount threshold.

    It does not

    Produce spending forecasts

    There is no forecast route. Forecasts come from the backend's statistical report analyzer; ml-service/forecast-payload.json is a leftover sample that nothing reads.

    It does not

    Store or expose user financial history

    Operates strictly on anonymized transaction descriptions and feedback labels. It has no access to user accounts, bank balances, or expense history.

    Active Limits & Maintenance

    Current engineering boundaries, operational assumptions, and tracked technical debt

    Current limit

    Rejecting a candidate strands its feedback

    The reject endpoint sets rejected but never releases the run's reserved corrections, and startup reconciliation only releases feedback for failed, failed_validation, failed_activation, and completed runs. Those rows stay reserved.

    Current limit

    Approval does not take the training lock

    Approve calls the activation workflow directly. Nothing in that endpoint stops it overlapping with another run's activation, unlike the automatic path, which holds the lock throughout.

    Current limit

    Gates judge accuracy only

    Macro-F1, per-class results, calibration, top-k recall, and baseline comparisons are recorded but no gate reads them. With ML_MAX_ACCURACY_REGRESSION unset the validator tolerates a 0.05 drop, not the documented 0.02.

    Current limit

    Abstention policy is provisional

    One global 0.90 threshold from a calibration run on duplicate-heavy, partly synthetic data. All fifteen per-class slots are empty until a versioned retrain or real feedback supports them.

    Current limit

    Prediction errors return HTTP 200

    The inference helper catches exceptions and returns an error body that the route does not turn into a non-2xx status. Express forwards such a body to the app as a 200.

    Current limit

    Keyword matching is substring-based

    Short keys fire inside unrelated words: web design course gets Electricity bill, cola gets Cab ride, and steak dinner gets Tea/snack expense.

    Current limit

    Workers need shared storage; deploy is not in code

    Workers on one disk converge; replicas on separate disks cannot. render.yaml defines only the backend web and worker, so this service's hosting is described by the Dockerfile and /data/models volume alone.

    Current limit

    Background work is one thread with no timeouts

    MongoDB makes concurrency and recovery safe, but there is no durable queue. The trainer and validator subprocesses have no timeout and heartbeats fire only between stages, so a stage longer than the stale timeout can be reclaimed while still running.

    Current limit

    Legacy bootstrap differs from the trainer

    The fixed legacy bundle is a 100-tree forest over 2,730 features with no metadata, while the trainer builds 30 trees over up to 1,000 features. Behavior can shift at the first activation.

    Maintenance

    Docs and APIs have drifted

    The service README lists GET /health and /ready while the real probes are /health/live and /health/ready, .env.example says a missing MONGO_CONN fails startup (it only warns), and FastAPI on_event plus naive utcnow() remain deprecated patterns.

    The architecture in one sentence

    Predict from one immutable snapshot. Abstain when unsure. Learn from reserved feedback. Validate, optionally approve, then publish. Roll back before risking the live model.
